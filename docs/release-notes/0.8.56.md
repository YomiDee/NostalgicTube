# NostalgicTube 0.8.56 (beta)

- Replace the 100% Random batch collector with a progressive stream. The first valid source can show two videos immediately, while remaining sources continue.
- Use six distinct searches and up to four videos per source, interleaving available sources towards a 24-video batch. Sampling terms, selected languages and date validation are retained.
- Preload one additional batch with two workers. If the user reaches the bottom early, reveal the partial reserve and stream its remaining results. Foreground requests use at most three workers.
- Deduplicate across sources and visible results, exclude the current video, discard stale responses and stop unstarted searches after throttling.
- Queue incremental native-card updates while YouTube initializes its grid, so new batches cannot discard earlier ones.
- Keep memory-only preloading bounded to one 24-video batch. First-load timing and total batch size depend on valid YouTube responses; this does not guarantee 24 results or a fixed loading time.

Validation: 61 automated tests pass. Tests cover early delivery before a slow response, 24 visible plus 24 buffered, partial reserve consumption, duplicates, source caps, concurrency, stale responses, rate limiting and native-render initialization races. Actual Brave/YouTube speed remains to be verified.

- Apply calendar dates only after pressing the small SVG checkmark in the red button. Closing without confirmation discards the pending date. Calendar confirmation and cancellation are covered by tests.
